# US Market Lens UI 规范与视觉设计说明

> 版本：1.0  
> 更新日期：2026-09-19  
> 适用范围：US Market Lens 的桌面端、移动端、数据页面、帮助面板及后续新增模块。

## 1. 设计定位

US Market Lens 是面向外贸、市场研究和供应链团队的企业级数据工作台。视觉上采用“可信、克制、可追溯”的数据产品风格：

- 以白色、浅灰和海军蓝构成主界面，避免消费级产品常见的高饱和渐变和装饰噪声；
- 重要数字优先，标题、说明、来源与数据状态形成清晰层级；
- 蓝色表示主要操作和官方数据，青色用于深色决策卡中的重点指标；
- 绿色、琥珀色、红色只承担成功、提醒、异常等语义，不作为大面积装饰；
- 所有图表和评分都必须可解释，视觉效果不能掩盖数据口径。

关键词：`Enterprise`、`Data-dense`、`Trustworthy`、`Traceable`、`Calm`。

## 3. 品牌规范

### 3.1 品牌组成

- 品牌 Logo：[`public/logo-sean.jpg`](../public/logo-sean.jpg)
- 产品名称：`US Market Lens.`
- 中文副标题：`美国进口决策工作台`
- Logo 默认尺寸：`40 × 40 px`
- Logo 容器：白色背景、`rounded-xl`、`slate-200` 边框、轻阴影
- 品牌名称使用海军蓝，结尾句点使用琥珀色作为微弱识别点

不要拉伸 Logo、改变长宽比、叠加滤镜，或将其放在复杂图片背景上。

### 3.2 品牌语气

- 中文是主要信息语言，英文只作为栏目 eyebrow 或专业缩写；
- 文字应直接说明“数据是什么、来自哪里、能证明什么”；
- 避免“AI 精准预测”“保证成交”“真实采购额”等无法由数据支持的表达；
- 风险和边界用明确的提示卡说明，不用模糊脚注隐藏。

| Navy | `#1A365D` | 品牌名称、激活导航、深色识别 |
| Dark panel | `#0D1724` | 决策摘要、品类 Hero、财务快照 |
| Muted text | `#64748B` / `#737373` | 辅助说明、次级信息 |

| Success | `#10B981` | 在线、已发布、正增长 |
| Danger | `#E7000B` / `#EF4444` | 错误、负增长、不可用 |

### 4.2 图表色板

| 顺序 | 色值 | 推荐用途 |
| --- | --- | --- |
| Chart 1 | `#1677FF` | 核心趋势、主要系列 |
| Chart 2 | `#63C5DA` | 第二系列或短周期数据 |
| Chart 3 | `#FFAD52` | 对比、提醒或次要分类 |
| Chart 4 | `#7D87B9` | 辅助系列 |
| Chart 5 | `#CBD2DA` | 基准、其他分类、弱化数据 |

同一张图优先使用一个主色。只有在需要区分多个语义系列时才扩展色板，避免“彩虹图表”。

### 4.3 语义色规则

- 成功：`emerald-50 / emerald-200 / emerald-700`
- 提醒：`amber-50 / amber-200 / amber-900`
- 错误：`red-50 / red-200 / red-700`
- 信息：`blue-50 / blue-100 / blue-700`
- 中性：`slate-50 / slate-200 / slate-600`

状态不能只靠颜色表达，必须同时提供文字，例如“已连接”“待配置”“暂时不可用”。

## 5. 字体与信息层级

### 5.1 字体栈

```css
font-family: Inter, "PingFang SC", "Microsoft YaHei", Arial, Helvetica, sans-serif;
```

编码、LEI、CIK、HS 等机器标识使用等宽字体：

```css
font-family: ui-monospace, SFMono-Regular, Menlo, Monaco, Consolas,
  "Liberation Mono", "Courier New", monospace;
```

### 5.2 推荐字号

| 层级 | 样式 | 使用位置 |
| --- | --- | --- |
| 页面主标题 | `text-2xl font-bold tracking-tight` | 页面名称 |
| Hero 标题 | `text-2xl` 至 `text-3xl font-bold` | 市场总览、品类摘要 |
| 模块标题 | `text-lg` 或默认字号 + `font-bold` | 卡片、表格、图表标题 |
| KPI 数字 | `text-2xl font-bold` | 核心金额、同比、份额 |
| 正文 | `text-sm leading-6` | 说明、规则、数据解释 |
| 辅助文字 | `text-xs` | 来源、单位、时间、口径 |
| Eyebrow | `text-[10px]` 至 `text-sm`、粗体、大写、加字距 | 英文模块标签 |

数字和结论使用高字重；来源、单位、期间使用低一层级，避免所有内容同时抢夺注意力。

## 6. 页面骨架

### 6.1 全局尺寸

| 区域 | 规范 |
| --- | --- |
| 最小视口 | `320 px` |
| 内容最大宽度 | `1480 px` |
| 页面水平内边距 | 手机 `16 px`；`sm` 为 `24 px`；`lg` 为 `32 px` |
| 页面垂直内边距 | 默认 `24 px`；`lg` 为 `32 px` |
| 展开侧栏 | `14rem` / `224 px` |
| 收起侧栏 | `4.25rem` / `68 px` |
| 顶栏最小高度 | `76 px` |
| 移动端底栏 | 最小 `64 px`，并包含安全区 |

所有业务页面统一使用：

```tsx
<main className="mx-auto w-full max-w-[1480px] px-4 py-6 sm:px-6 lg:px-8 lg:py-8">
```

### 6.2 桌面端结构

1. 左侧为可收缩白色导航栏；
2. 顶部为粘性工具栏，包含当前模块、全局搜索、帮助和状态标签；
3. 主内容区使用浅灰背景，卡片按数据阅读顺序从上到下排列；
4. 页面标题区与第一组内容保持约 `24 px` 间距；
5. 同组卡片常用 `gap-3 / gap-4 / gap-5`。

### 6.3 响应式断点

项目使用 Tailwind 默认断点：

| 断点 | 宽度 | 行为 |
| --- | --- | --- |
| `sm` | `640 px` | 表单从纵向变横向，KPI 可变两列 |
| `md` | `768 px` | 显示桌面侧栏；隐藏移动端底部导航 |
| `lg` | `1024 px` | 增加页面留白，显示右侧状态标签，部分区域变双列或三列 |
| `xl` | `1280 px` | 显示顶栏模块说明，KPI 常用四列，主次内容形成非等宽分栏 |

移动端不缩小桌面布局，而是重新排列：表单堆叠、卡片单列、底部六项导航固定、主内容增加底部 `pb-20`。

## 7. 间距、圆角与阴影

- 全局基础圆角 Token：`0.7rem`；
- 业务卡片统一使用 `rounded-xl`；
- 输入框、小按钮和行内模块使用 `rounded-lg`；
- 胶囊筛选和标签使用 `rounded-full`；
- 卡片边界：`border border-slate-200`；
- 普通卡片阴影：`shadow-sm`；
- 顶栏阴影：`0 6px 24px rgba(15, 23, 42, 0.035)`；
- 侧栏阴影：`4px 0 24px rgba(15, 23, 42, 0.035)`；
- 移动端底栏阴影：`0 -8px 30px rgba(15, 23, 42, 0.08)`。

阴影只用于建立层级，不用于制造悬浮感。一个页面内不应同时出现多种浓重阴影。

## 8. 背景与视觉效果

### 8.1 页面背景

页面使用非常轻的蓝灰渐变和右上角径向蓝光：

```css
background-image:
  radial-gradient(circle at 80% 0%, rgb(219 234 254 / 48%), transparent 28rem),
  linear-gradient(180deg, #f8fafc 0%, #f3f6fa 100%);
```

该效果只用于增加空间感，不能抢过图表和 KPI。

### 8.2 半透明层

顶栏、侧栏和移动端导航使用 `bg-white/95 + backdrop-blur-xl`。透明度必须足够高，确保滚动内容不会影响文字可读性。

### 8.3 Hover 与动效

- 可点击卡片：边框由 `slate-200` 变 `blue-200`，背景由浅灰变浅蓝；
- 导航激活：浅蓝背景、海军蓝文字，并显示左侧 `3 px` 激活条；
- 链接箭头：Hover 时右移约 `2 px`；
- 加载：使用 `animate-spin`；计算或洞察生成可使用轻量 `animate-pulse`；
- 不使用弹跳、连续缩放、粒子、霓虹发光或长时间自动动画；
- 所有过渡保持短促，优先 `transition` 默认时长。

## 9. 核心组件规范

### 9.1 页面标题区

标准结构：英文 eyebrow → 中文主标题 → 一行说明 → 右侧状态或操作。

```tsx
<p className="text-sm font-semibold text-blue-700">DATA EXPLORER</p>
<h1 className="mt-1 text-2xl font-bold tracking-tight">官方贸易数据检索</h1>
<p className="mt-2 text-sm text-slate-500">按 HS、来源地和年度检索。</p>
```

### 9.2 标准白色卡片

```tsx
<section className="rounded-xl border border-slate-200 bg-white p-5 shadow-sm lg:p-6">
```

卡片内部顺序：标题和说明 → 主内容 → 来源、时间或操作。不要把来源信息放在视觉上比主指标更强的位置。

### 9.3 KPI 卡片

- 标签：`text-xs text-slate-500`，可配 `16 px` 图标；
- 主值：`text-2xl font-bold`；
- 解释：`text-xs text-slate-400`；
- 正增长用绿色，负增长用红色，中性数值使用 `slate-950`；
- 一组 KPI 在 `sm` 为两列、`xl` 为四列。

### 9.4 深色决策卡

- 背景：`#0D1724`；
- 主文字：白色；辅助文字：`slate-300 / slate-400`；
- 强调：`cyan-300`；
- 内嵌区域：`border-white/10 bg-white/5`；
- 只用于 Hero、决策摘要、真实性规则和财务快照，不要让整个页面变成深色。

### 9.5 按钮与输入框

- 顶栏标准控件高度：`40 px`；页面主表单高度：`44 px`；
- 主按钮：`blue-600`，Hover 为 `blue-700`；
- 次按钮：白底、浅灰边框；
- 帮助按钮：浅蓝背景和蓝色边框；
- 输入框默认浅灰背景，聚焦时变白；
- 图标位于文字前，常用尺寸 `16–18 px`；
- 禁用态必须降低对比度并禁止交互。

### 9.6 Badge

- Badge 用于来源、状态、期间、口径和轻量分类；
- 一条 Badge 只表达一个含义；
- 成功、提醒、错误遵循语义色；
- 不要把长句放进 Badge。

### 9.7 表格

- 容器：白色卡片、圆角、浅边框、轻阴影；
- 表头：`bg-slate-50`；
- 主要字段左对齐，金额与比例右对齐；
- 编码字段使用等宽字体；
- 主值用中等或粗体，完整金额或补充信息放下一行并弱化；
- 行操作使用 Ghost Button，避免每行出现高饱和主按钮；
- 小屏幕允许横向滚动，不挤压列到不可读。

### 9.8 帮助抽屉

- 从右侧打开，最大宽度 `560 px`；
- 顶部白色标题区，主体使用 `#F7F9FC`；
- 内容顺序：项目用途 → 三步操作 → 注意事项 → 推荐工作流；
- 操作步骤使用编号圆点和统一图标；
- 帮助文字要解释业务含义，不复述按钮名称。

## 10. 图表规范

### 10.1 通用规则

- 图表库：Recharts；
- 标准图表高度：`280 px`；复杂矩阵可使用 `380 px`；
- 图表放在白色卡片内，标题下保留约 `20 px` 间距；
- 网格线使用 `#E8EDF3` 和 `4 4` 虚线；
- 通常关闭坐标轴轴线和刻度线；
- 趋势线宽度使用 `3 px`；
- 面积图渐变从约 `0.3` 透明度降到 `0.02`；
- Tooltip 必须展示单位和业务字段名；
- 标题下明确单位、期间、来源国和数据范围；
- 金额使用统一缩写函数，详细值可在副行或 Tooltip 中展示。

### 10.2 图表选择

| 需求 | 图表 |
| --- | --- |
| 年度趋势 | 折线图或面积图 |
| 最近月份 | 柱状图 |
| 品类规模排行 | 横向柱状图 |
| 份额与增长关系 | 散点 / 气泡图 |
| 来源国相对规模 | 表格内进度条 |

不要使用 3D 图、仪表盘堆叠、饼图爆炸效果或无法直接比较的装饰图形。

## 11. 页面状态

每个异步页面必须包含以下状态：

### 11.1 Loading

- 白色卡片或浅灰占位区；
- 蓝色旋转图标或轻量脉冲；
- 一句当前动作和一句预期耗时/数据行为；
- 已有旧数据时保留旧数据，只在刷新按钮显示旋转状态。

### 11.2 Empty

- 使用低对比度图标；
- 明确告诉用户尚未输入、没有结果或数据尚未发布；
- 给出下一步，而不是只显示“暂无数据”。

### 11.3 Error

- `red-50` 背景、`red-200` 边框、`red-700` 文字；
- 说明是参数问题、上游失败还是网络失败；
- 可以重试时提供清晰操作。

### 11.4 Warning / Boundary

- 使用琥珀色提示卡；
- 适合采购额边界、来源限制和口径风险；
- 文字必须说明“不能推导什么”及“需要什么证据补充”。

### 11.5 Success / Live

- 使用绿色 Badge；
- 区分“实时官方数据”“内置官方快照”“已发布”“已连接”；
- 不要把缓存数据标记为实时数据。

## 12. 图标规范

- 图标库统一使用 Lucide React；
- 常规尺寸 `16–18 px`，模块图标 `20 px`，空状态 `36–40 px`；
- 图标与文本同时出现，不使用难以理解的纯图标操作；
- 同一功能跨页面使用同一图标，例如搜索、数据库、帮助和刷新；
- 图标线条颜色跟随语义色，不单独创造新颜色。

## 13. 可访问性

- 所有可交互控件必须支持键盘；
- `:focus-visible` 使用 `3 px`、海军蓝 18% 透明度焦点环；
- 导航激活项使用 `aria-current="page"`；
- 纯图标按钮必须有 `aria-label` 或 `title`；
- 正文与背景保持足够对比度；
- 状态不能只依赖红绿颜色；
- 点击目标建议不小于 `40 × 40 px`；
- 外部链接明确显示外链图标并保留来源名称；
- 页面语言固定为 `zh-CN`。

## 14. 新页面模板

新增分析页面时，建议采用以下顺序：

1. 页面标题区；
2. 筛选器或主要动作；
3. Loading / Error / Empty 状态；
4. 3–4 个 KPI；
5. 主图表与次要解释；
6. 明细表格；
7. 来源、更新时间和口径提示；
8. 对应帮助中心内容。

新增页面同时需要：

- 在 `primaryNav` 中补充导航名称、英文 eyebrow、描述和 Lucide 图标；
- 在帮助中心加入用途、三步操作、注意事项与下一步；
- 复用全局 Token，不新增无必要的硬编码颜色；
- 验证桌面展开侧栏、桌面收起侧栏和手机底栏三种状态。

## 15. 禁止事项

- 不使用大面积高饱和渐变；
- 不使用厚重投影、玻璃拟态叠层或霓虹发光；
- 不在一张卡片中混用多个主色；
- 不用红色表示普通重点信息；
- 不用超大数字遮盖上下文、单位和期间；
- 不用动画替代状态文字；
- 不把市场汇总与企业采购额放在同一视觉层级而不解释口径；
- 不为单个页面创造独立导航、圆角、按钮或图表语言。

## 16. 开发验收清单

- [ ] 页面使用统一 `max-w-[1480px]` 容器和响应式内边距；
- [ ] 卡片为白底、浅边框、`rounded-xl`、轻阴影；
- [ ] 标题、主值、单位、来源和时间层级清楚；
- [ ] 图表颜色、网格、Tooltip 和单位符合规范；
- [ ] Loading、Empty、Error、Warning 状态齐全；
- [ ] 状态同时使用颜色和文字；
- [ ] 桌面侧栏可展开/收起，移动端底栏不遮挡内容；
- [ ] 键盘焦点和 `aria-label` 可用；
- [ ] 页面帮助内容已同步；
- [ ] `npm run lint` 与 `npm run build` 通过；
- [ ] 在 `320 px`、`768 px`、`1280 px` 和宽屏下检查布局；
- [ ] 数据来源、统计期间和业务边界没有被视觉弱化或遗漏。
