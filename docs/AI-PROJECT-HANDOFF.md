# US Market Lens 项目说明与 AI 接手手册

> 最后更新：2026-09-18  
> 面向对象：后续接手本项目的 AI、开发者、数据工程师和产品负责人  
> 当前形态：局域网内免登录访问的 Docker Web 应用，端口 `7022`

## 1. 一句话说明

US Market Lens 是一个面向外贸销售、采购研究和市场分析人员的美国进口情报工作台。它优先使用免费、公开、可追溯的数据源，帮助用户分析：

- 美国从某个国家或地区进口了多少钱；
- 哪些 HS 品类规模最大、增长最快；
- 某家美国企业是否真实存在、是否上市、有哪些公开财务和联邦业务记录；
- 数据来自哪里、更新到什么时候、哪些指标可以使用、哪些指标不能冒充企业采购额。

项目的核心原则不是“尽量显示更多数字”，而是“只显示能说明来源和口径的数字”。

## 2. 最重要的数据真实性边界

本项目同时处理三类容易混淆的数据。后续 AI 必须始终区分：

| 数据类型 | 能回答什么 | 不能回答什么 |
| --- | --- | --- |
| 国家级贸易汇总 | 美国从中国、越南等来源地进口了多少钱；某 HS 品类规模多少 | 不能归属于某一家企业 |
| 企业公开资料 | 企业身份、上市代码、财务报表、联邦奖项 | 不能直接证明企业采购额或供应商国家 |
| 海运提单资料 | 海运批次、重量、柜量、供应商、供应国、产品描述 | 通常不能证明真实成交金额；不完整覆盖空运和陆运 |

以下等式全部是错误的，禁止在界面、接口、文档或洞察中使用：

- SEC 营业成本 ≠ 企业采购额；
- SEC 库存或应付账款 ≠ 年度进口额；
- USAspending 联邦奖项金额 ≠ 企业采购金额；
- UN Comtrade 某国对美出口额 ≠ 某家美国客户的采购额；
- 估算运费 ≠ 商品成交金额；
- 海运提单数 ≠ 商品件数。

只有客户授权的订单、ERP、报关单、付款记录或其他可审计资料，才能标记为“企业实际采购额”。

## 3. 当前已实现的产品能力

### 3.1 市场总览 `/`

- 选择一个来源国家或地区；
- 查看最近五个完整年度的美国进口总额；
- 查看最近已发布月份；
- 查看八个重点 HS 章节的金额结构；
- 查看年度趋势、品类柱状图和年度明细表；
- 中国数据带有经过核验的内置快照，上游接口繁忙时仍能展示基础数据；
- 明确提示这些金额是国家级汇总，不是企业采购额。

### 3.2 企业情报 `/companies`

用户输入企业名称或股票代码后，系统并行查询：

- SEC EDGAR：上市公司名称、CIK、Ticker；
- GLEIF：法律实体名称、LEI、注册地址、实体状态；
- USAspending：美国联邦资金受款方与奖项金额。

对于匹配到的上市公司，还可继续加载：

- 企业基本资料、行业、注册州；
- 最近五年的营业收入、营业成本、毛利、库存、资产、应付账款；
- 最近的 10-K、10-Q、8-K、20-F、40-F 文件。

这些数据用于企业识别和公开经营信息核验，不提供该企业的进口提单、供应商国家或真实采购额。

### 3.3 数据检索 `/search`

- 按 HS 2、4、6、10 位编码查询；
- 支持输入多个 HS 编码；
- 支持中文品类关键词匹配 HS 章节；
- 选择来源地和年度；
- 返回美国进口金额、是否找到记录、是否为聚合记录；
- 查询结果可继续进入品类钻取。

### 3.4 品类钻取 `/drilldown`

- 查看某个 HS 编码最近五年金额；
- 计算同比、复合增长率、份额和波动率；
- 查看最近三个月月度数据；
- 对比重点来源国；
- 通过查询参数接收 `hs` 和 `partner`。

### 3.5 洞察中心 `/insights`

- 对八个重点 HS 章节计算增长、份额与机会分；
- 展示增长最快、规模最大、降幅最大的品类；
- 提供机会矩阵和排行榜；
- 机会分公式公开，不使用不可解释的黑箱模型。

当前公式：

```text
机会分 = 50 + 同比增长 × 1.4 + 品类占来源地进口份额 × 1.2
份额贡献上限为 25，最终结果限制在 0—100。
```

机会分只用于市场筛选，不替代客户订单、价格、毛利和竞争信息验证。

### 3.6 数据治理 `/sources`

- 检测各免费数据源是否在线；
- 显示数据源权威机构、覆盖范围、更新频率、金额口径和 Key 要求；
- 显示内存缓存状态；
- 使用 World Bank 数据交叉检查美国商品进口宏观趋势；
- 展示“指标与证据字典”；
- 可以导出当前市场、数据源和宏观数据的 JSON 证据快照。

### 3.7 全局交互

- 桌面端白色企业侧栏，宽度支持 `224px ↔ 68px` 收起和展开；
- 侧栏状态保存在浏览器 `localStorage`；
- 移动端使用侧栏抽屉和六模块底部导航；
- 顶部全局搜索会把纯数字识别为 HS 编码，其他文本识别为企业名称；
- 每个页面都有“帮助”按钮，说明页面用途、步骤、口径和下一步；
- 当前模块在侧栏和移动导航中均有明确选中状态；
- 无登录和密码，这是用户明确要求的局域网部署方式。

## 4. 当前不能实现的能力

### 4.1 不能免费自动得到企业真实年度采购额

免费公开来源无法稳定给出“某企业一年采购了多少美元”。要实现该指标，必须接入至少一种授权数据：

- 客户订单；
- ERP 或采购系统；
- 报关单；
- 付款或发票数据；
- 经授权的商业海关数据库。

### 4.2 当前主界面不能直接查询企业供应商和来源国

这需要公司级提单数据。目前代码中保留了 ImportYeti API 连接路由，但默认禁用，因为 ImportYeti 账户没有 API credits，且正式 API 要求配置付费 Key。

不能为了“免费接入”直接把 ImportYeti 网页抓取作为正式数据接口。网页结构易变，也需要先确认服务条款、访问频率和授权范围。

### 4.3 即使接入提单，也要限制产品表述

提单功能应显示为：

- 最近 12 个月海运批次；
- 总重量、件数、柜量或 TEU；
- 来源国家分布；
- 海外供应商排名；
- 到港日期、提单号、产品描述等证据记录；
- 数据覆盖与保密提示。

不得把它命名为“真实采购额”，除非记录中确实包含可审计的成交金额并且授权允许使用。

## 5. 数据源说明

### 5.1 UN Comtrade Public API

用途：项目主要贸易数据源。

- 权威机构：United Nations；
- 当前使用：美国作为报告国，进口作为贸易流；
- 维度：来源地、HS 编码、年度或月份；
- 金额：`primaryValue`，缺失时回退到 `cifvalue`；
- 免费且无需 Key；
- 来源地字典来自 UN Comtrade reference table；
- 客户端对请求做串行限速、重试、去重和内存缓存。

限流策略：

```text
同一进程最小请求间隔：1050 ms
429 重试次数：最多 3 次
默认缓存时间：6 小时
同一 URL 的并发请求：合并为一个 in-flight Promise
```

主要代码：

- `lib/comtrade-client.ts`
- `lib/comtrade-reference.ts`
- `app/api/comtrade/*`

### 5.2 SEC EDGAR

用途：美国上市公司识别、公开财务和文件。

- 企业检索：SEC full-text search；
- 企业资料：submissions API；
- 财务数据：XBRL companyfacts；
- 免费且无需 Key；
- 请求带有项目 User-Agent；
- 财务年度按事实记录的实际 period end 分组，避免把 10-K 中重复列示的历史对比数据误标为当前年度。

重要限制：营业成本、库存、应付账款是财务指标，不是采购额。

### 5.3 GLEIF LEI API

用途：企业法律身份核验。

- 法律名称；
- LEI；
- 注册地址；
- 管辖地；
- 实体和 LEI 注册状态；
- 最近更新日期。

免费且无需 Key，不提供进口金额或采购金额。

### 5.4 USAspending API

用途：查询企业或机构作为美国联邦资金受款方的记录。

- 可返回受款方名称、UEI、DUNS 和奖项金额；
- 免费且无需 Key；
- 联邦奖项表示该实体收到的美国政府资金，不是该企业向供应商支付的采购金额。

### 5.5 World Bank Open Data

用途：宏观交叉校验。

- 指标：美国商品进口金额；
- 年度更新；
- 免费且无需 Key；
- 只用于验证总体趋势，不提供企业、来源国或 HS 明细。

### 5.6 U.S. Census International Trade API

用途：更细粒度的美国官方进口数据。

- 维度可包括国家、HS10、月份、运输方式；
- 可返回金额、数量、重量、海运金额、空运金额等字段；
- API Key 免费，但需要用户自行申请并配置；
- 当前后端接口已实现；未配置 Key 时返回 `503 source_not_configured`；
- 它仍然是市场聚合数据，不是单个公司的采购记录。

环境变量：

```text
CENSUS_API_KEY=
```

### 5.7 ImportYeti（可选、默认禁用）

用途：企业级美国海运提单、供应商和供应国关系。

项目中已有两个可选后端路由：

- `GET /api/importyeti/search?q=<公司名称>`；
- `POST /api/importyeti/company`，请求体包含公司 slug。

只有配置 `IMPORTYETI_API_KEY` 后才启用。当前账户没有 credits，因此主产品不依赖该数据源，也没有把它算入免费已连接数据源。

环境变量：

```text
IMPORTYETI_API_KEY=
```

不要把 ImportYeti 的 `Est. Shipping Spend` 当作采购额；它表示估算运输支出。

## 6. 数据可信等级

后续新增字段时，建议沿用以下等级：

| 等级 | 标识建议 | 说明 |
| --- | --- | --- |
| 官方汇总 | `official_aggregate` | UN Comtrade、Census、World Bank 等官方或国际组织汇总 |
| 官方公司披露 | `official_company_disclosure` | SEC 文件和 XBRL |
| 实体登记 | `legal_entity_record` | GLEIF LEI |
| 公开政府业务 | `public_award_record` | USAspending |
| 观察到的提单 | `observed_manifest` | ImportYeti 或其他提单资料 |
| 规则推导 | `derived_from_official_aggregate` | 机会分、同比、CAGR、份额、波动率 |
| 客户授权事实 | `customer_authorized_actual` | ERP、订单、报关单或付款数据 |

每个新增指标应至少包含：来源、统计范围、时间范围、单位、更新时间、可信等级和限制说明。

## 8. 技术结构

```text
浏览器
  └─ AppShell
      ├─ 可收缩桌面侧栏
      ├─ 移动端抽屉与底部导航
      ├─ 全局搜索
      ├─ 页面帮助中心
      └─ 六个产品页面
          └─ 本项目 API Routes
              ├─ Comtrade 网关：限速、缓存、重试、请求合并
              ├─ Open Data 客户端：缓存、超时、重试
              └─ 可选 Census / ImportYeti 连接器
                  └─ 外部官方或授权数据源
```

主要技术：

- TypeScript；
- React 19；
- Vinext / Next App Router 兼容层；
- Vite；
- Cloudflare Worker / Wrangler 本地运行环境；
- Tailwind CSS；
- Shadcn/Radix UI 组件；
- Recharts；
- Docker Compose。

项目当前没有业务数据库。缓存存在 Node/Worker 进程内存中，容器重启后会清空。

## 10. 运行与部署

### 10.1 当前局域网部署

```sh
docker compose up -d --build
```

默认访问：

```text
http://<宿主机局域网 IP>:7022/
```

本次搭建时使用的地址为：

```text
http://<宿主机局域网 IP>:7022/
```

局域网 IP 可能随网络环境改变，不应硬编码到业务代码。

### 10.2 状态与日志

```sh
docker compose ps
docker compose logs -f us-market-lens
```

容器带健康检查，正常状态应为 `healthy`。Dockerfile 使用非 root 的 `node` 用户运行，Compose 开启 `no-new-privileges`。

### 10.3 本地构建

```sh
npm run build
```

### 10.4 停止服务

```sh
docker compose down
```

这会停止并删除容器，但不会删除项目源代码。当前没有业务数据库卷。

## 11. 环境变量和密钥规则

`.env.example` 当前包含：

```text
CENSUS_API_KEY=

```

规则：

- 使用项目根目录 `.env`；

## 12. 用户与 AI 如何一步步把项目搭建出来

下面是需求演进和关键决策。它既是产品历史，也是后续 AI 理解用户真实优先级的依据。

### 阶段 1：最初目标——免费查询美国客户采购情况

用户提出：

> 做一个免费的应用，查美国客户每年的采购额、品类分析；如果有现成 GitHub 方案，可以先借鉴。

由此确定了最初方向：美国进口贸易研究工具，优先免费和可复用方案。

### 阶段 2：真实性和及时性成为第一优先级

用户明确强调：

> 这个项目最重要的是数据真实及时。

产品策略随之调整：不再使用演示数字冒充真实业务数据；所有指标必须有数据源、时间和限制说明。

### 阶段 3：要求局域网、免密码、固定端口

用户要求：

> 数据直接写好，局域网能访问，不需要密码，端口 7022。

系统因此采用局域网部署，监听 `0.0.0.0:7022`，没有登录层。后续 Docker 也保持这一要求。

### 阶段 4：从单页原型升级为企业工作台

用户反馈第一版太简单：

> 只有一个页面？搜索、钻取、洞察呢？我要企业级能用的。

应用由单页扩展为六个模块：市场总览、企业情报、数据检索、品类钻取、洞察中心、数据治理。

### 阶段 5：验证“按客户看来源国采购”的可行性

用户继续追问：

> 输入一个客户，能看到他从哪些国家分别采购了多少东西，可以吗？

在此阶段明确了国家级贸易汇总与企业级提单的区别：UN Comtrade 可以回答美国整体从各国进口多少，但不能回答某一家企业从各国采购多少。

### 阶段 6：调查 ImportYeti API

用户注册 ImportYeti 后发现：

> No API access yet. To start using the API, please purchase credits.

结论是：ImportYeti 网站可能提供部分公开查看能力，但 API 自动接入需要 credits。项目保留可选连接器，不伪造免费 API，也不默认抓取网页。

### 阶段 7：把能合法免费接入的数据全部接上

用户要求：

> 把能免费接上的数据全部接上，然后再打分。

项目接入：

- UN Comtrade；
- SEC EDGAR；
- GLEIF；
- USAspending；
- World Bank；
- U.S. Census 可选免费 Key。

并增加数据治理页面，明确每个来源的口径和在线状态。

### 阶段 8：再次确认企业采购额和来源国边界

用户提出：

> 单个企业真实采购额及来源国有办法获得吗？及时性差点没关系。

得到的产品结论是：

- 企业真实采购额需要客户授权数据；
- 来源国、供应商和海运量可以通过提单数据库获得；
- 免费公共源不能同时稳定满足“企业 + 金额 + 来源国 + 供应商”四个维度。

### 阶段 9：Docker 化

用户要求：

> 把这个项目 Docker 容器化，端口 7022。

随后增加 Dockerfile、Compose、健康检查、非 root 运行和局域网端口映射。

### 阶段 10：增加全站使用帮助

用户要求每个页面提供 `?` 按钮和图文说明。项目增加了统一帮助中心，根据当前路由解释页面用途、数据边界和操作步骤。

### 阶段 11：修复导航并参考 3010 项目重做 UI

用户反馈：

> 其他模块都点不开，侧边栏要支持缩放，UI 学一下 3010 的项目。

排查发现，当前 Vinext 运行环境中的框架 Link 组件在浏览器发生 RSC 导航错误，表现为链接获得焦点但不跳转。处理方式：

- 站内关键链接改为可靠的原生导航；
- 保留客户端控件和数据交互；
- 参考本机 3010 项目的信息架构，把侧栏改为白色企业风格；
- 支持 `224px ↔ 68px` 收缩和状态记忆；
- 增加当前模块标题、蓝色激活标记；
- 增加移动端底部导航和抽屉；
- 统一时间格式，消除服务端和浏览器时区造成的 hydration 错误。

注意：当前代码中使用原生 `<a href>` 进行关键页面跳转是有意设计，不要未经验证全部换回 `next/link`。

### 阶段 12：用户提出最终理想查询方式

用户的目标表达为：

> 输入客户名字，想查他一年进口量多少，从哪里进口，谁卖给他的。

这定义了下一阶段最重要的产品方向：企业供应链画像。实现它需要 ImportYeti 等授权 API、用户导入的提单 CSV，或客户自有报关/ERP 数据。

## 13. 后续最合理的开发路线

### 方案 A：导入提单 CSV，保持低成本

新增“企业供应链”模块，让用户上传其有权使用的 CSV：

1. 映射企业名称、地址、提单号、到港日期；
2. 统一供应商和国家名称；
3. 按最近 12 个月聚合提单数、重量、件数、柜量；
4. 分别按单位统计，禁止把 kg、pcs、ctn 直接相加；
5. 展示来源国占比、供应商排名和证据明细；
6. 记录导入文件、时间和字段映射。

这是当前最可控、最合规、最接近“免费”的企业级方案。

### 方案 B：配置商业提单 API

若用户购买 ImportYeti credits 或其他供应商 API：

1. 启用已有 ImportYeti 后端连接器；
2. 在公司搜索结果中先做实体消歧；
3. 按地址和别名合并公司记录；
4. 获取最近 12 个月提单；
5. 对国家、供应商、重量、柜量和品类进行聚合；
6. 在每个数字旁显示数据覆盖、更新时间和证据记录；
7. 追踪 API credit 消耗并设置缓存和每日预算。

### 方案 C：接入客户 ERP/报关资料

如果目标是真实采购金额，这是唯一可靠路线。建议数据模型至少包含：

- buyer；
- supplier；
- origin_country；
- order_date / customs_date；
- hs_code；
- quantity 和 quantity_unit；
- amount 和 currency；
- incoterm；
- source_document_id；
- audit_status。

## 14. 接手 AI 的行为规则

1. 先保护真实性边界，再扩展功能。
2. 不得把市场汇总值写成企业采购值。
3. 不得为了页面完整而生成虚构企业、供应商、金额或提单。
4. 上游失败时应显示错误、缓存或已标注的官方快照。
5. 每个数据源都要标明权威机构、更新时间、口径和限制。
6. 涉及 ImportYeti 或其他商业源时，先确认 API 权限、credits 和授权范围。
7. 修改 UI 时同时验证桌面侧栏、收起状态、移动抽屉和底部导航。
8. 关键导航当前使用原生链接；如要恢复 SPA 导航，必须先解决 Vinext RSC Link 错误并完成浏览器实测。
9. 保持端口 `7022`、局域网访问和免登录，除非用户明确改变要求。
10. 如果准备暴露到互联网，必须先向用户说明免登录带来的数据和访问风险，并增加访问控制。

## 16. 当前已知限制与技术债

- 没有业务数据库，缓存重启即失效；
- 没有用户账户、权限或审计日志；
- 无法保存客户清单、查询历史和收藏；
- 企业搜索依赖名称匹配，仍需要人工确认地址和法律实体；
- Comtrade 公共接口有频率和记录限制；
- 中国快照只保障默认总览的基础可用性，其他来源地没有本地快照；
- Census 需要单独配置免费 Key；
- ImportYeti 自动查询需要付费 credits；
- 公司级供应国、供应商和进口量尚未进入主界面；
- 当前洞察规则只覆盖八个重点 HS 章节，不代表完整行业模型。

## 17. 当前项目状态摘要

项目目前已经是一个可实际使用的免费美国进口市场分析工作台，而不是只展示静态数字的单页原型。它适合做市场规模、来源地、HS 品类、企业身份和公开经营资料的初步研究。

它还不是完整的企业供应链数据库。用户最终想要的“输入公司名，得到最近一年进口量、来源国和供应商”需要下一阶段接入提单数据；“真实年度采购额”则必须依赖客户授权数据。

接手者应把这两项作为下一阶段方向，同时保持当前项目最重要的产品资产：数据真实、口径清楚、来源可追溯。
